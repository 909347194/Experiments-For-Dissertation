## LLM 增强 DMDE 的可行性分析

### 一、LLM-MOEA 核心机制回顾

LLM-MOEA 的关键设计：

- **算子选择**：LLM 根据搜索状态选择交叉/变异算子
- **自适应周期**：每 p 代收集优化轨迹，组装提示词
- **特征抽象**：剔除实例依赖特征（如具体目标函数值），保留搜索依赖特征（如种群多样性、收敛趋势）
- **上下文学习**：无需微调，靠 prompt 工程驱动决策

---

### 二、DMDE 当前的自适应瓶颈

| 模块         | 当前做法                                    | 局限                                     |
| ------------ | ------------------------------------------- | ---------------------------------------- |
| 混合差分策略 | 公式 3-9/3-10：CR 和 F 按固定公式随代数衰减 | 无法感知搜索状态，衰减节奏与问题难度无关 |
| 灭绝算子     | 公式 3-12：CR < δ 时概率触发                | 阈值 δ 固定，不区分"真收敛"和"假停滞"    |
| 反映射扰动   | top_k 线性衰减 8→1，扰动概率 40%→2%         | 衰减曲线固定，不感知种群多样性           |
| 约束处理     | β 固定惩罚系数                              | 约束违背严重时无自适应调整策略           |

**共性问题**：所有自适应参数都用**预设公式**驱动，不感知**当前搜索状态**。

---

### 三、LLM 可增强的具体环节

#### 3.1 差分策略的动态选择

当前 DE/rand/1（探索）和 DE/best/2（开发）的切换由 CR 公式决定。LLM 可以：

- **感知**：种群多样性指标（如基因值方差、最优解停滞代数）
- **决策**：在 rand/1、best/2、current-to-best、rand/2 等更多策略中选择
- **理由**：当种群高度聚集时，选择更具探索性的策略；当种群分散但收敛慢时，选择开发型策略

**示例提示词**：

```
当前状态：种群多样性=0.12（低），停滞代数=15，CR=0.35
历史轨迹：近10代最优适应度从596k→594k（微弱改善）
请从以下差分策略中选择最适合当前状态的：
1. DE/rand/1（强探索）
2. DE/best/2（强开发）
3. DE/current-to-pbest/1（平衡）
并说明理由。
```

#### 3.2 反映射温度的自适应调节

当前温度线性衰减 `1.0 - gen/max_gen`，与搜索状态无关。LLM 可以：

- **感知**：可行解比例、约束违背趋势、种群适应度方差
- **决策**：温度衰减速率、是否需要"升温"（跳出局部最优）
- **理由**：当可行解比例持续为0时，保持高温增加探索；当可行解出现后，快速降温精细开发

#### 3.3 灭绝算子的触发判断

当前 GMR 灭绝由 CR < δ 概率触发，本质是"代数到了就灭绝"。LLM 可以：

- **感知**：种群收敛程度（最优/最差适应度比）、多样性丧失速度、是否陷入早熟
- **决策**：是否触发灭绝、灭绝比例（保留多少精英）、是否需要"定向重启"（向特定区域注入新个体）
- **理由**：区分"正常收敛"和"早熟停滞"，避免不必要的灭绝浪费计算资源

#### 3.4 约束处理策略

当前用固定 β 惩罚约束违背。LLM 可以：

- **感知**：各约束类型的违背量分布、可行解与不可行解的适应度差距
- **决策**：调整 α/β 权重、切换到可行性规则（feasibility-first）、或采用ε-约束方法
- **理由**：当所有解都严重不可行时，降低约束权重先找"大致可行"区域；当接近可行时，增大约束权重精细修复

#### 3.5 SRP 巡游顺序的修复

当前 SRP 的 sequence_group 约束无法被保证（seq_violation=1.0）。LLM 可以：

- **感知**：哪些 UAV 的巡游顺序违反了时序约束
- **决策**：给出具体的基因重排方案（如"将 T0 移到 T1 之前"）
- **理由**：基于问题结构理解，比随机扰动更精准

### 四、LLM 增强的架构设计思路

```
DMDE 主循环
    │
    ├── 每 p 代触发一次 LLM 决策
    │       │
    │       ├── 收集特征（剔除实例依赖）
    │       │     - 种群多样性
    │       │     - 收敛速度
    │       │     - 可行解比例
    │       │     - 约束违背分布
    │       │     - 停滞代数
    │       │
    │       ├── 组装提示词
    │       │     - 当前特征
    │       │     - 历史决策及效果
    │       │     - 可选算子列表
    │       │
    │       ├── LLM 推理
    │       │     - 输出：算子选择 + 参数调整 + 理由
    │       │
    │       └── 回传决策
    │             - 更新 CR/F 策略
    │             - 更新温度衰减
    │             - 更新灭绝参数
    │
    └── 继续进化 p 代
```

### 五、关键挑战与风险

| 挑战           | 说明                                                                              |
| -------------- | --------------------------------------------------------------------------------- |
| **推理延迟**   | LLM 调用耗时（秒级），DMDE 每代进化仅毫秒级。p 需足够大（如50~100代）才能摊薄开销 |
| **决策质量**   | LLM 不一定比精心设计的数学公式更优，尤其在简单问题上                              |
| **可复现性**   | LLM 输出有随机性，同一批输入可能给出不同决策，影响实验可复现性                    |
| **提示词设计** | 特征选择、提示词格式、few-shot 示例的质量直接决定 LLM 决策质量                    |
| **成本**       | API 调用费用，尤其大规模实验时                                                    |

---

### 六、适合引入 LLM 的场景

| 场景                   | 适合度 | 理由                                 |
| ---------------------- | ------ | ------------------------------------ |
| 大规模问题（50U/50T+） | ⭐⭐⭐ | 搜索空间大，固定公式难以覆盖所有状态 |
| 约束密集问题           | ⭐⭐⭐ | 约束类型多、交互复杂，需要动态权衡   |
| 多目标优化             | ⭐⭐⭐ | 帕前沿维护需要策略切换               |
| 小规模问题（5U/5T）    | ⭐     | 固定公式已足够，LLM 开销不值得       |
| 实时/在线调度          | ⭐     | 推迟迟不可接受                       |

---

### 七、结论

LLM 增强 DMDE 的核心价值在于**将"固定公式驱动的自适应"升级为"搜索状态感知的智能决策"**。但需要权衡：

- **收益**：在复杂、大规模、多约束场景下，LLM 的上下文理解能力可能找到公式难以覆盖的策略组合
- **代价**：推理延迟、API 成本、可复现性下降

建议先在**约束密集的 N>M 场景**中验证（当前 sync 违约问题最突出），用 p=50 代的间隔调用 LLM，对比固定公式的基线效果。
