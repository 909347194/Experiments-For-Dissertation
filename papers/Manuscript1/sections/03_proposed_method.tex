As shown in \figref{fig:framework}, the framework keeps the DE main loop intact
and attaches two LLM-driven modules to it. \popinit{} is invoked once, before
generation~0, to seed the population; \crctrl{} is invoked every $I$ generations
to re-tune \CR{}. Both modules share the same LLM client and the same
constraint-repair utility, so a candidate produced by the LLM is only accepted
after being repaired to feasibility.

\subsection{LLM-Guided Population Initialization}
\label{subsec:popinit}

\popinit{} asks the LLM for a small number of high-quality candidate solutions
and injects them into an otherwise random initial population. The proportion of
injected individuals is controlled by a ratio parameter
$\rho \in (0, 1)$, so the method reduces to vanilla DMDE as $\rho \to 0$.

\begin{algorithm}[htbp]
  \caption{\popinit{}}
  \label{alg:popinit}
  \begin{algorithmic}[1]
    \State \textbf{Input:} scenario description, population size $\NP$,
           injection ratio $\rho$, preference list of top-$k$ candidates
    \State \textbf{Output:} initial population $P_{0}$
    \State $P_{0} \gets$ uniformly sampled random individuals
    \State $S \gets$ LLM(scenario description, preference list)
    \State $S' \gets$ \textsc{RepairAndDeduplicate}$(S)$
    \State replace $\lceil \rho \NP \rceil$ random individuals of $P_{0}$ with
           $S'$
    \State \Return $P_{0}$
  \end{algorithmic}
\end{algorithm}

A candidate is discarded when it cannot be repaired to feasibility, in which
case the corresponding slot keeps its randomly sampled individual. This guard is
essential: in the scarce-resource scenario almost none of the LLM outputs
survive repair, so \popinit{} has to degrade gracefully rather than inject
infeasible solutions. % 待补：结合实验数据说明两个场景下修复成功率的差异

\subsection{LLM-Guided Adaptive Crossover Rate Control}
\label{subsec:crctrl}

\crctrl{} re-tunes \CR{} every $I$ generations. Unlike a one-shot prompt, the
controller is fed back the outcome of its previous decision: the \CR{} value in
force, the number of generations elapsed, the relative fitness change, and the
change in population diversity. The decision loop is therefore closed, and the
prompt exposes the \CR{} actually used in each recent generation.

\begin{algorithm}[htbp]
  \caption{\crctrl{}}
  \label{alg:crctrl}
  \begin{algorithmic}[1]
    \State \textbf{Input:} current generation $g$, interval $I$,
           fitness and diversity statistics of the last interval
    \State \textbf{Output:} crossover rate for the next interval
    \State \textbf{if} $g \bmod I \neq 0$ \textbf{then} keep current \CR{}
    \State build prompt: recent trajectory (with per-generation \CR{}),
           previous \CR{} decision, fitness/diversity response
    \State $\CR^{\star} \gets$ LLM(prompt)
    \State \Return clip($\CR^{\star}$, $\CR_{\min}$, $\CR_{\max}$)
  \end{algorithmic}
\end{algorithm}
